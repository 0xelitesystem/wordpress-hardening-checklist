# Updates and plugins

Keep WordPress core, themes, and plugins updated, and remove any you do not use, because outdated and abandoned plugins are the leading way real WordPress sites get compromised. Every plugin is code running on your site, and unmaintained code is a known risk.

## Why plugins are the top risk

WordPress core is maintained closely, but the plugin ecosystem is enormous and uneven. A vulnerability in a popular plugin can expose every site running an outdated copy of it, and attackers actively scan for exactly that. The plugins you install are as much a part of your security as the core, and an old plugin with a known flaw is an open invitation.

## Update promptly

Apply updates to core, themes, and plugins promptly, because updates frequently fix security flaws that are already public and being exploited. The window between a fix being released and an old version being attacked can be short. Where automatic updates for security releases are available and safe for your site, they reduce the chance of falling behind. Test significant updates if you can, but do not let updates pile up unapplied.

## Remove what you do not use

Every installed plugin and theme is attack surface, even when deactivated, because the code still sits on the server. Delete plugins and themes you are not using rather than leaving them dormant. A smaller set of active, maintained components is both easier to keep current and a smaller target. The default should be to remove, not to keep just in case.

## Install from trusted sources

Install plugins and themes only from reputable sources, and prefer ones that are actively maintained with a recent update history and a real user base. Code from unknown or pirated sources can carry malware directly. An abandoned plugin that has not been updated in years is a future vulnerability waiting to be found, so factor maintenance into what you choose to install.

## Audit periodically

On a regular schedule, review what is installed, confirm everything is current, and remove anything abandoned or unused. Plugins accumulate over time, and a site that was tidy a year ago can drift into carrying a dozen risks. A periodic audit keeps the set small, current, and trusted, which is most of what plugin security requires.
